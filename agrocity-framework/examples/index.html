Introducción

Framework UI ligero, sin dependencias runtime. CSS + JS vanilla. Tema claro/oscuro. Inspirado en Bootstrap 5 y Material Design.

CDN

<link rel="stylesheet" href="https://cdn.example.com/agrocity-kit.min.css" />
<script src="https://cdn.example.com/agrocity-kit.min.js"></script>
<script src="https://cdn.example.com/agrocity-icons.min.js"></script>

Estructura base

<!DOCTYPE html>
<html lang="es" data-theme="light">
<head>
  <link rel="stylesheet" href="agrocity-kit.min.css" />
</head>
<body class="ak-body">
  ...
  <script src="agrocity-kit.min.js"></script>
</body>
</html>

Tema oscuro

Cambia a data-theme="dark" en el <html> o usa AgrocityKit.theme('toggle').

Tema personalizado

Usá AgrocityKit.setTheme({ light: {...}, dark: {...} }) para sobrescribir los tokens de color. Inyecta reglas :root y [data-theme="dark"] custom.

AgrocityKit.setTheme({
  light: {
    '--ak-primary': '#8B5E3C',
    '--ak-primary-light': '#C49A6C',
    '--ak-secondary': '#5C4033',
    '--ak-secondary-dark': '#3E2723',
    '--ak-secondary-light': '#8D6E63',
    '--ak-bg': '#FFF8F0',
    '--ak-surface': '#FFF8F0',
    '--ak-surface-alt': '#F5EDE4'
  },
  dark: {
    '--ak-primary': '#C49A6C',
    '--ak-primary-light': '#8B5E3C',
    '--ak-secondary': '#A1887F',
    '--ak-secondary-dark': '#4E342E',
    '--ak-secondary-light': '#8D6E63',
    '--ak-bg': '#1A1410',
    '--ak-surface': '#2C221C',
    '--ak-surface-alt': '#3E322B'
  }
});

Tema mínimo (con derivación automática)

Ahora setTheme() genera automáticamente las variables hover, on-* y alpha a partir de los colores base. Solo necesitás definir los colores principales.

// Solo colores base — el resto se deriva automáticamente:
AgrocityKit.setTheme({
  light: {
    '--ak-primary': '#1B6B3A',
    '--ak-secondary': '#1A4B7A',
    '--ak-bg': '#F0F7F4'
  },
  dark: {
    '--ak-primary': '#4CAF66',
    '--ak-secondary': '#6488BB',
    '--ak-bg': '#0E1A14'
  }
});
// Auto-genera: --ak-primary-hover, --ak-on-primary,
// --ak-primary-alpha-04..50, --ak-secondary-hover, etc.

Formularios

Inputs, selects, textareas, file uploads, floating labels, input groups, checkboxes, radios, switches, datepicker, timepicker y validación reactiva.

Estructura general

Cada campo se envuelve en .ak-form-field-content que agrupa .ak-form-label + el input/select/textarea. Los feedbacks de validación se auto-crean dentro de este contenedor.

<div class="ak-form-field-content">
  <label class="ak-form-label">Etiqueta</label>
  <input class="ak-form-control" />
  <!-- .ak-invalid-feedback se crea automáticamente -->
</div>

1. Text inputs

Inputs de texto básicos, email, número, teléfono, URL, contraseña y textarea. Usan .ak-form-control.

<div class="ak-form-field-content">
  <label class="ak-form-label" for="id">Texto</label>
  <input type="text" class="ak-form-control" id="id"
    data-ak-validate="required|email|min:3|max:100"
    data-ak-msg="Campo requerido"
    data-ak-msg-email="Email inválido"
    required />
</div>
AtributoDescripción
type="text|email|number|tel|url|password"Tipo de input HTML
class="ak-form-control"Clase base para todos los inputs
.ak-form-control-smInput pequeño
.ak-form-control-lgInput grande

<!-- Custom múltiple con popover -->
<input type="file" class="ak-form-file-input" multiple

Auto-star

Si el label dentro de .ak-form-field-content no tiene <span class="ak-asterisk-field">*</span> y el campo tiene required, el framework lo agrega automáticamente al inicializar el formulario. El asterisco tiene color rojo (var(--ak-danger)) y margin-left: 2px.

Campos soportados
Tipo de campoContenedor de errorFeedback CSS

Textarea.ak-form-control.ak-is-invalid ~ .ak-invalid-feedback
Select nativo.ak-form-select.ak-is-invalid ~ .ak-invalid-feedback
Custom Select.ak-select.ak-has-error + .ak-select__error-msg
DatePicker.ak-datepicker.ak-is-invalid ~ .ak-invalid-feedback

Comportamiento
  • Los feedbacks .ak-invalid-feedback se crean automáticamente si no existen
  • Las etiquetas .ak-form-label cambian a rojo cuando el campo es inválido
  • El formulario se valida en blur/input/change después del primer submit (o al tocar el campo)
  • Checkbox/radio validan solo en change
  • El submit se intercepta automáticamente; si hay errores enfoca el primer campo inválido
  • Los Custom Select, DatePicker, TimePicker y File Input se detectan automáticamente

// Inicialización manual
AgrocityKit.formValidation('init', '#miForm', {
  onSuccess(form) {
    AgrocityKit.showToast('Guardado', { type: 'success' });

    AgrocityKit.showToast('Corrige los errores', { type: 'danger' });
  }
});

// Re-validar un campo específico

Carga en cascada con data-ak-geo-value

Para precargar valores (ej. al editar), agrega data-ak-geo-value en los campos municipality y neighborhood. Apenas se poblen las opciones, se asigna ese valor y se dispara change automáticamente para continuar la cascada. El atributo se elimina tras aplicarse.

<select data-ak-geo-name="dir" data-ak-geo-state>
  <!-- se llena con estados -->
</select>
<select data-ak-geo-name="dir" data-ak-geo-municipality
        data-ak-geo-value="015">
  <!-- se llena y auto-selecciona municipio 015 -->
</select>
<select data-ak-geo-name="dir" data-ak-geo-neighborhood
        data-ak-geo-value="CENTRO">
  <!-- se llena y auto-selecciona colonia CENTRO -->
</select>
